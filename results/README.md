Comparisons: [before vs after](compare.md), [before vs ablation](compare-ablation.md) (made with `redteam compare`).

**Ablation.** `secure-naive-model` is the secure target with the heuristic and prompt-level layers switched off (input guardrail, document sanitiser, untrusted wrapper, hardened-prompt behaviour), as in `tests/test_secure_scan.py`. The 8 that fire again are LLM01-001 to 006, LLM01-008 and LLM08-001: prompt-injection attacks that rely on those soft layers. All tool, disclosure, HTML, limit and prompt-leak attacks stay blocked by real code (authorisation, escaping, limits).

**What MOCK can and cannot prove:** MOCK shows that the code-level controls (authorisation, escaping, limits, rate limiting) block these attack payloads regardless of model, but the prompt-level defences are only simulated by a deterministic stand-in, so it proves nothing about how a real LLM would behave.
